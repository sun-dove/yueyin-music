# 视频同款002：独立安卓构建与签名

日期：2026-10-30。依据：用户已确认《视频同款安卓应用-设计与验收》并授权开工，设计明确允许独立安装包标识及稳定签名。

## 原因与兼容边界

视频同款应用需要与既有 Mconnect 同时安装，后续可用相同签名升级。原工程默认包名、应用名及 debug 签名保持原行为；仅在构建进程明确设置 `VIDEO_MUSIC_BUILD=1` 时启用独立应用配置。

接入点仅为 `android/app/build.gradle.kts` 的构建选择及主清单的应用名称占位符。既有公开 Dart 接口、原入口与默认构建不改。

## 受影响调用方

- 原 `flutter build apk`：未设置开关时仍生成 `com.mconnect.mconnect`、应用名 Mconnect，并使用原 debug 签名。
- 新 `scripts/build_video_apk.ps1`：设置开关并指定 `lib/main_video.dart`，生成 `app.videomusic.player`、应用名“同款音乐”，当前版本 0.3.0，使用任务专用稳定签名；下方 0.1.0 表格属于历史构建记录。
- Android 清单合并：`appLabel` 占位符由对应构建分支提供；默认值仍为 Mconnect。
- 视频同款发布：沿用按架构分包，不输出通用包；不会覆盖或卸载用户现有 Mconnect。

## 构建环境与私有材料

工具链位于工作区 `work/toolchains`，使用本机已有 Java 17。Android SDK 包均从 Google 官方分发地址经官方 `redirector.gvt1.com` 获取，并核对仓库元数据提供的 SHA-1；直接 `dl.google.com` 在本机返回 404，故采用官方重定向通道。Flutter 固定 3.47.5。

同一网络问题也影响 Google Maven。视频同款构建脚本仅向任务自己的 Gradle 用户目录复制带开关的初始化脚本，优先使用阿里云 Google Maven 镜像及 Maven Central；分别覆盖 settings 与插件 buildscript 仓库，避免向 Flutter included build 的项目仓库注入配置。不开启视频同款构建时该脚本不生效，不改用户全局仓库配置。

稳定签名位于工作区 `work/signing`，不进入源码及提交。构建读取 `VIDEO_MUSIC_SIGNING_PROPERTIES` 指定的私有配置，不打印密码；密钥必须保留以支持后续覆盖升级。应用使用该独立包标识，签名切换不影响原包已安装用户。

SDK、NDK、模拟器与必要构建依赖属于可复用构建环境。下载压缩包、一次性安装脚本、模拟器 PID 及运行日志在构建验收结束后核对精确路径清理；运行中的模拟器先正常停止。

## 回滚方案

不设置 `VIDEO_MUSIC_BUILD` 即恢复原构建行为；删除新增构建脚本及回退本票据列出的两个配置差异即可还原源码。原应用数据没有迁移或改写。视频同款独立包可单独卸载，但后续升级应保留其稳定签名。
