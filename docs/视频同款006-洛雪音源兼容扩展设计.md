# 视频同款006：洛雪音源兼容扩展设计

日期：2026-11-02。状态：用户已确认顺带修复部分音源不能导入。

## 背景与目标

0.3.1 在 Android 隔离沙箱逐个导入 `pdone/lx-music-source` 的 16 个入口，8 个初始化通过，8 个失败。所有脚本均下载成功且未超过 1 MiB；失败分为同步脚本异常、初始化请求超时和缺少洛雪工具接口。

目标是提升可解释性并兼容能在现有安全边界内实现的常用能力。不能通过暴露文件系统、账号存储、原生网络、`require`、`process` 或 DOM 来追求全兼容；上游服务不可达也不能伪装成客户端兼容成功。

## 方案比较

### 方案 A：将脚本放入 WebView/Electron 风格完整环境

兼容面较大，但会重新暴露 DOM、浏览器网络和更多主机能力，破坏已经验收的隔离边界，Android 资源与生命周期成本高，不采用。

### 方案 B：扩展最小洛雪兼容层

继续使用 AndroidX JavaScriptEngine 独立进程。先把同步异常、网络失败和缺 API 分类清楚，再实现纯计算型 `lx.utils`、常用编码能力及兼容请求参数；网络仍只走受控桥。这是推荐方案。

## 接口与数据结构

- `LxSandbox` 公开接口不变。
- 沙箱错误返回增加受限的错误类别与最多 160 字消息，不返回脚本正文、响应体或本地路径。
- `lx.utils` 仅增加可在沙箱内纯计算或由受控主机桥实现的接口。禁止动态代码加载、文件、系统命令、账号存储和直接网络。
- 初始化网络响应继续限制 HTTPS、无重定向、512 KiB、请求数和超时；兼容常见 `body`/`raw`/header 形状。

## 场景与验收门

1. 同步初始化异常显示具体受限原因；缺 API 显示接口名。
2. buffer/base64/UTF-8 等纯计算能力有黄金用例，恶意超大输入被拒绝。
3. 初始化请求非 2xx、超时和解析错误能回传给脚本 callback，不把错误吞成永远等待。
4. 脚本仍看不到 `require/fetch/Java/process/document`，死循环和取消仍能终止。
5. 重新核对 16 个固定入口，逐个记录初始化结果；初始化通过不当作真实歌曲播放通过。
6. 全量既有自动化保持通过。

## 实现步骤与回滚

先新增错误分类及 utils 红门，再最小实现并运行固定脚本验收；不能安全兼容的接口保持明确不支持。回滚为移除新增兼容函数，恢复 0.3.1 bootstrap；已保存脚本配置无需迁移。最终 APK 不打包第三方脚本。
