# 悦音音乐：多音源、最高可用音质与 QQ 播放诊断

日期：2026-11-02。状态：用户已确认“按修订方案开始实现（推荐）”，授权第二稿的新增模块、独立入口接入、最高音质策略及兼容修复。实现和主机验收已完成：1806 项通过、11 项既有跳过、0 失败，静态 0 issue。新版设备逐源初始化及真实歌曲播放待具备设备条件，不能以主机结果代替。

## 背景与目标

用户要求保存多个音源，播放失败时自动切换，并询问关闭音源后是否仍可使用 QQ 音乐，以及为何部分 QQ 收藏歌曲无法播放。

补充场景：用户提供《窝囊废》，提示“该歌曲在 QQ 音乐不可用”，并说明该曲需要 VIP；歌手、曲目 MID、用户实际会员状态和官方 App 是否能完整播放尚未确认。用户还希望接近洛雪的多源可用性，并明确优先最好音质。因此本稿增加播放顺序选项、跨源的最高可用音质策略以及更完整的洛雪接口适配，不能只做列表存储。

已核对 0.3.2 的实际代码：

- `VideoPreferences` 只保存一份 `video.lxSource.config`；再次保存会替换上一份。
- `VideoPlaybackPlatform.getSongUrl` 先调用官方平台。自定义源只有在已启用、支持当前平台，并遇到歌曲不可用、会员不可用或所选音质不可用时才参与；未开启音源也会请求 QQ 官方播放地址。
- 独立播放器坚持用户选定音质，不自动降音质或跳到下一首。收藏同步和播放取流是不同请求，收藏同步成功不代表取流成功。
- `VideoCatalog._parseQqSong` 未保留 `file.media_mid` 和歌曲类型；数字 ID 仅放在收藏操作的内部映射中。`LxSourceRuntime.resolve` 把 `song.id` 同时写入 `songmid` 和 `songId`，没有传 `strMediaMid`。这与洛雪 QQ 曲目结构中三个独立标识的约定不一致。
- QQ 官方取流沿用 `vkey.GetVkeyServer/CgiGetVkey`，文件名由歌曲 MID 重复拼接，歌曲类型固定为 0。缺少媒体标识时这是已有回退方式，但没有利用歌曲真实的媒体文件标识。
- QQ 取流数据为空与部分响应异常最终都变成“该歌曲在 QQ 音乐不可用”，当前提示不足以判明原因。
- 旧播放器的整次 `getSongUrl` 外层只有 10 秒，而 LX 运行时单源超时是 15 秒。把多个源简单串在现有调用中，会在轮询尚未结束时被外层提前中止。
- 当前音源回退只覆盖地址解析失败；取得地址后加载失败、播放中途错误不会换到下一个自定义源。
- “我的”里的标准音质来自播放偏好，缺省为标准，并非逐曲探测出的唯一可用音质。现有选择器已列出标准、HQ、SQ、Hi-Res 和母带，但没有按源能力说明能否尝试；播放页的请求档位、资源格式和码率是不同信息。
- `lx_bootstrap.dart` 的 crypto 与 zlib 当前全部抛“不支持”异常；buffer 仅实现部分接口，`currentScriptInfo` 也是占位信息。洛雪原实现包含 MD5、AES、RSA、安全随机字节、buffer、压缩解压及真实脚本元数据。只保存更多脚本无法消除这些兼容缺口。

上述是代码事实及兼容缺口，不是对《窝囊废》失败原因的最终结论。VIP 要求可以解释部分官方请求失败，但启用第三方源仍需该源实际支持歌曲并提供有效地址。当前播放器会原样显示合并的官方/自定义源错误，没有证据表明这条提示是被国际化覆盖丢失；不能仅凭用户转述认定音源已请求或未请求。不读取或导出用户 Cookie。

目标是保留当前默认行为，增加可保存、排序、启停的音源列表、可选择的自动切换和最高可用音质策略，补齐 QQ 曲目标识、洛雪常用接口和错误说明。保持当前歌曲，固定音质模式不降档，最高可用模式明确展示降档过程，避免错误版本替换、无限重试和误播上一首。

## 两个方案比较

| 方案 | 实现及影响 | 结论 |
| --- | --- | --- |
| A：在现有单源解析器内部循环多个源 | 代码较少，但旧 10 秒整次超时会截断循环；无法覆盖得到地址后的加载失败和播放中错误；会直接改变已有解析器行为 | 不采用 |
| B：新增列表存储、独立播放协调器与版本化兼容层，在独立入口选择使用 | 保留旧公开接口和默认单源路径；以“源、音质”组合管理超时、取消与错误；补齐脚本所需接口，可覆盖解析、加载和播放中错误，并向 UI 报告进度 | 推荐 |

不新增外部服务，不预装第三方脚本，不升级现有依赖。兼容层若需引入经过核验的纯 JavaScript 计算实现，只作为明确版本、许可和来源的隔离运行时资产，不安装或暴露 Node/Electron。继续使用现有隔离沙箱和受控网络桥。

推荐的新设置组合为“音源优先、自动切换、最高可用音质”，本轮已获用户确认。旧配置缺少新增字段时仍保持官方优先、单源、固定音质；在新页面明确选择推荐组合后才启用新行为，不静默修改老用户设置。

## 用户可见行为

1. 音源页面改为列表，能保留用户给出的仓库内全部 16 个脚本，不以一条或八条为上限。每个源显示名称、版本、声明的平台和音质、已启用/已停用、初始化结果，以及设为首选、上移/下移、更新和删除操作。“已导入”“已初始化”“该曲播放成功”分开显示，不能混为可用。
2. 导入成功后先加入待保存列表；新源默认关闭。相同标准化链接更新同一条记录，保留排序、启用状态和下载选项；同名但不同链接可以分别保存。失败时不覆盖现有记录。
3. 原来保存的一个源自动出现在列表中，保留启用和下载选项。增加“自动切换音源”开关，缺省关闭，用户开启后才改变失败处理行为。
4. 播放顺序可选“官方优先”和“音源优先”，推荐后者以贴近用户的自定义音源使用目标。同一音质内，官方优先为官方、首选音源、其他启用源；音源优先为首选音源、其他启用源、官方。关闭自动切换只使用所选模式下的单源候选及原官方回退规则，不扩展到多个脚本；全部源关闭时仍使用官方。
5. 音质提供“最高可用”和“固定音质”两个模式。最高可用按 Hi-Res、无损、320k、128k 的标准梯度，从高到低生成候选：同一档位先试全部符合条件的源，再进入下一档，不能 A 源给出 128k 就跳过尚未尝试的 B 源无损。官方专有档位保留手动选择，有明确支持证据时才加入自动候选，不能把通用脚本请求伪装成母带。固定模式坚持所选音质。两种模式都保持同一平台的同一首歌，不自动搜索翻唱或替换其他版本。
6. 取流失败、音频地址加载失败或播放中途明确报错时，尝试下一个符合条件的源。播放中途切换保留进度，资源不支持定位时明确提示从头播放。正常缓冲、暂停和播放结束不触发换源。
7. 正在换源时显示“正在尝试 星海 · 无损”；进入低一档时明确提示“无损暂不可用，正在尝试 HQ”。音频加载成功后显示实际来源、请求档位，以及有证据的媒体格式/码率。仅得到 URL 不显示“播放成功”，脚本声明或请求参数不能作为实测音质。没有媒体证据时显示“音质待验证”。全部失败停留在当前歌曲，展示逐项原因和重试入口。
8. QQ 已识别的登录过期立即提示重新登录并保持原会话失效处理，不以换源伪装登录成功。新增自动模式下可跳过失效的官方候选，继续用户明确启用且无需该账号的自定义源；禁用新模式时保留旧失效触发矩阵。明确网络错误可继续下一候选；未知内部程序错误明确停止，避免掩盖程序问题。
9. 每个“源 ID、音质、用途”组合在一轮内最多尝试一次；源级初始化不兼容等错误会跳过该源余下档位，歌曲/音质级错误按类别继续。相同失败 URL 不重复装载。请求取消、切歌、停用自定义源、删除正在尝试的源或用户暂停时，旧轮次失效，迟到结果不能继续播放。
10. 每个 LX 候选沿用最多 15 秒解析预算，单次媒体加载最多 10 秒，整轮自动恢复最多 45 秒。达到整轮上限时明确显示已尝试与未尝试的源和档位，提供“继续尝试”；不得把未尝试项标为失败或声称已找到全部源中的最高音质。继续创建新时间预算并保留已尝试组合，不能从第一个坏源重来；同档尚有未试候选时不直接降档。
11. 下载只使用明确允许下载的源。关闭自动切换时沿用单源规则；开启时可对取下载地址失败依次尝试符合下载条件的源。已经开始的文件传输失败不拼接其他音源的内容，仍走原下载错误与重试流程。
12. 播放质量与下载质量独立保存。列表可显示“源声明支持无损”，单曲只有真实取流和媒体加载成功才显示对应可播放状态，不把设置页的“标准”当成该曲只有标准。

## 洛雪兼容范围与验收口径

本轮目标是支持多个用户导入的洛雪脚本并扩展其 QQ/网易云播放能力；不因脚本声明多个平台就自动新增酷我、酷狗或咪咕的搜索、账号与歌单系统。

- 对照洛雪原实现补充脚本元数据、同步 crypto（MD5、AES、RSA、安全随机字节）、buffer 的数据类型和编码语义，以及异步 zlib 压缩/解压。同步方法不能用 Promise 冒充；随机字节来源必须是系统安全随机，不能用 `Math.random` 替代。
- 新兼容层独立命名/版本化，旧 bootstrap 与旧运行时默认调用保持不变。新增沙箱纯计算资产或受限操作桥，不开放账号凭据、文件、系统命令、DOM 或任意网络入口。
- 验收包括上游约定的黄金向量、返回类型、参数错误、二进制往返、输入/解压输出上限、取消和资源回收。未支持的方法明确显示名称，不能返回空值假装成功。
- 用户给的 `pdone/lx-music-source` 本轮只读目录核对仍有 16 个 `latest.js`。实施时固定各脚本的提交/哈希并逐个记录下载、初始化、QQ/网易云声明档位、实际指定歌曲取流及媒体加载结果；任何未测档位明确写未测，不抽样冒充全覆盖。
- 脚本可导入但服务返回无资源、需要源自身的访问凭据、仅支持某个平台、要求桌面环境或服务不可达时，分别记录，不能承诺 16 个全部能播。若设备仍不可用，交付明确说明未做真实 Android 逐源播放验收，不把主机黄金门当作替代。
- 不在普通 Node 进程执行外部混淆脚本，不把 Node vm 当作安全边界；源码阅读和黄金向量与第三方脚本设备执行分开。

## 接口、存储与兼容

新增独立类型，以下是设计契约，名称在实现前固定：

- `LxSourceCollectionEntry`：`id`、现有 `LxSourceConfig config`。顺序来自集合中的列表；不更改 `LxSourceConfig` 的既有字段语义。
- `LxSourceCollection`：`schemaVersion = 1`、`entries`、可空 `preferredSourceId`、`autoSwitch = false`，追加可选 `sourceOrder`，缺省 `officialFirst`。无首选或首选被停用时使用列表中第一个启用源。
- 新 `VideoPlaybackPolicy`：可选 `qualityMode`（缺省 `fixed`）与标准档位上限；`highestAvailable` 为新增模式。播放和下载分开保存。推荐组合明确写入 `sourceFirst + autoSwitch + highestAvailable`，不能通过字段缺失偷偷启用。
- `LxSourceCollectionStore`：追加 `loadCollection`、`saveCollection`；存入新键 `video.lxSource.collection.v1`。新键不存在时从旧键构造一条记录；旧键不删除，不重解释旧 `setLxSource`/`loadLxSource` 的契约。集合保存后，将当前首选镜像到旧单源键；无启用源时镜像为关闭。新键存在但损坏时显示恢复提示，不静默清空音源。
- `VideoQqSongMetadata`：`songMid`、可选数字 `songId`、可选 `mediaMid`、可选 `songType`。通过独立目录适配器与元数据存储补充，不修改 `Song.id`、相等性、收藏 ID 或既有公共模型。老收藏缺少信息时按 MID 或数字 ID 查询详情并缓存，不把猜测的数字 ID 传给脚本。
- 新增 QQ 取流适配器：在独立入口选用，利用真实媒体标识、歌曲类型和已有完整会话；旧 `QqApi.getSongUrl` 与原 QQ 平台接口不改。先验证详情与取流响应样本，再固定新请求契约；不以改接口名就宣称修复。非成功响应保留错误类别，缺字段视为协议/资源问题，不能无依据提示用户购买会员。
- 新增 LX 曲目适配器：仅有可靠元数据时补充 `songId`、`songmid`、`strMediaMid`；其他平台和缺省调用继续使用原运行时。必要时追加新方法，不直接改变已使用的 `resolve` 默认行为。
- `MultiSourcePlaybackCoordinator`：创建带 generation、歌曲键、音质策略、用途和候选快照的播放会话。最高可用模式按音质外层、源顺序内层形成候选；固定模式只生成一个档位。管理取消、时间预算、尝试记录及当前有效源。
- `SourceAttempt`：包含源 ID/名称、请求音质、阶段（初始化/解析/加载/播放）、明确错误类别、结果（尝试中/成功/失败/不适用/未尝试/已取消）、源级或档位级作用范围和是否可重试；不保存带令牌的 URL、Cookie 或响应正文。
- 新媒体证据结构区分 `requestedQuality`、`declaredQualities`、可空 `observedFormat/Bitrate/SampleRate/BitDepth` 与加载状态；既有 LX 结果把请求档位写入 `actualQuality` 的行为不得成为新 UI 的实测依据，也不为修显示而改变旧结果的公共契约。
- 新版本化 LX 运行时及兼容 bootstrap 通过现有 `LxSourceEngine` 接口注入；同步计算和异步受限桥按上文的兼容范围实现，保留旧默认实现。
- `MultiSourceVideoPlayerNotifier` 与必要的控制器装饰器：通过现有平台和音频控制器注入点接入。多源解析不放在旧单次 `getSongUrl` 的 10 秒计时器里；每次交给原播放器的是已解析候选。恢复从播放器锁外执行，不能形成嵌套锁或让迟到事件推进新歌曲。
- 新增播放来源状态供新 UI 使用；原 `VideoStreamInfo` 和旧调用方缺省行为保留。解码器成功装载后再把候选标为当前来源。

## 必须改动的入口、调用方与回滚

必要的现有路径改动只有独立入口的装配、新 UI 入口以及接入元数据的适配点。原因是现有页面只有单条配置，现有播放器只理解单次解析；新增模块必须经装配才能对用户生效。以下清单随用户确认本设计一并确认后才能实施：

| 接入位置 | 受影响调用方 | 边界与回滚 |
| --- | --- | --- |
| `lib/main_video.dart` 的源存储、平台、播放器、下载解析注入 | 悦音音乐独立 Android 入口 | 恢复 0.3.2 注入，原 `lib/main.dart` 不变 |
| `VideoMusicApp` 的自定义音源入口及播放器状态显示 | 我的页面、音源页面、播放页面 | 恢复旧页面路由和来源字段显示；旧页面组件接口保留 |
| 新 QQ 目录/播放适配器的独立入口选择 | 搜索、QQ 收藏列表、播放与下载元数据读取 | 取消选择新适配器；收藏标识和原账户存储不迁移 |
| 新多源配置键及首选单源镜像 | 独立入口源存储、新 UI、新协调器 | 旧版本仍读首选镜像；不删除集合或用户已保存脚本 |
| 新兼容运行时的独立入口选择 | 新音源导入、测试及播放协调器 | 恢复旧运行时注入；第三方脚本保留，不修改旧引擎接口 |

不修改既有公开方法签名、返回类型或原入口行为。实现如需额外触及公共播放器生产路径，先补充本票据的原因、调用方与回滚，确认范围后再改。

APK 回滚继续使用原包名与签名、递增构建号，不要求卸载和清空配置。

## 场景与可执行验收门

确认后先把下列场景写成可执行红门，再实现；现阶段仅设计，未声称这些门已执行或通过。UI 期望反向约束返回状态与错误类别。

| 场景 | 体验门 | 确定性功能门 |
| --- | --- | --- |
| 原用户升级 | 原源仍可见，开关及下载选项不变 | 单源迁移、重启恢复、重复迁移幂等、缺省关闭自动切换 |
| 导入 A、B、更新 A | 两条记录都保留，失败不覆盖 | 增加、去重、同名不同链接、完整持久化、写入失败不报成功 |
| 多源配置 | 可排序、选首选、启停、删除 | 顺序、首选回退、禁用和删除持久化；旧键镜像正确 |
| 没有启用源 | QQ/网易云官方仍可播放 | 官方调用一次，自定义源零调用 |
| 官方优先与音源优先 | 同档位按所选顺序显示尝试来源 | 精确候选顺序，候选成功后停止；旧固定/官方优先模式官方成功时其他源零调用 |
| 官方失败、A失败、B成功 | 尝试状态更新，显示 B，仍是当前歌曲 | 精确候选顺序、每组合最多一次、无跳曲 |
| 关闭自动切换 | 首选失败后显示原因，不再尝试 B | 旧单源触发矩阵不变 |
| 不支持当前平台或音质 | 明确标记不适用 | 不执行不适用脚本；正确计算候选数 |
| A返回URL但音频无法加载 | 继续 B，不能提前显示播放成功 | 模拟真实加载失败、重复URL、成功状态在装载后产生 |
| 播放中途错误 | 尝试下一源、保留进度或明确提示从头播放 | 异步错误、定位失败、旧完成事件、正常暂停/缓冲不换源 |
| 官方及所有源失败 | 留在当前歌，展示逐项原因和重试 | 无无限循环、错误分类完整、无未说明的降档或错歌 |
| 取消或切歌 | 不再出现旧歌来源提示或声音 | generation、旧结果、并发快速切歌、删除/停用、暂停 |
| 预算耗尽 | 显示已试/未试数及继续按钮 | 虚拟时钟验证单源和总预算，继续不重复已试源；不得默默只测前 N 个 |
| QQ标识不同/老收藏缺元数据 | 能解析的播放，失败有具体原因 | 数字 ID/MID/mediaMID 区分、songType 保留、详情补全、未知字段不伪造 |
| QQ账号或音质错误 | 登录错误给重登入口，音质错误给手动调整入口 | 成功/空资源/会话失效/明确权益限制/未知协议错误分别断言 |
| A只支持标准、B支持无损 | 最高可用模式播放 B 的无损，不能先接受 A 标准 | 按音质外层遍历，标准源不抢先结束；固定模式仍只试所选档位 |
| 全部高音质失败而HQ成功 | 明确提示降档并显示成功来源 | 高档候选已完成或不适用后才降低档位，不静默截断候选 |
| 仅有脚本声明或请求档位 | 显示声明/请求和“音质待验证” | 没有码率/位深证据不能制造实测值；同一低质 URL 不伪装成多个高档位 |
| 缺失crypto/zlib/脚本元数据 | 能兼容的初始化成功，不能兼容的显示具体接口 | 上游黄金向量、同步/异步返回类型、编码往返及资源限制先红后绿 |
| 16个脚本逐项兼容 | 各自显示导入、初始化和实际播放结果 | 固定脚本哈希、平台/档位矩阵、未测项明确标记；初始化不冒充播放 |
| 下载和离线 | 离线仍可播，未允许下载的源不参与 | 本地零网络、下载候选过滤、不跨源拼接文件、播放取消不误取消下载 |
| 兼容及实际设备 | 旧体验不退化，设备边界如实标明 | 既有全量回归、静态检查；真实 Android 导入和歌曲播放另验 |

无需大模型参与这些判断。源顺序、状态机、字段映射、错误码及测试断言均为确定性逻辑，不强行使用 Jev。

## 实现步骤

1. 用户确认此设计；对失败歌曲收集最小复现信息，不要求提供凭据。
2. 写多源持久化、UI、最高可用音质遍历、来源顺序、加载/中途失败、超时和取消场景红门；对 QQ 字段和洛雪兼容接口写黄金样本门。
3. 先落地独立存储与列表，再接入播放协调器和来源状态；旧单源和原 Mconnect 门保持通过。
4. 根据经过核验的 QQ 详情/播放响应补齐元数据与独立适配器，修复 LX 数字 ID/媒体标识映射；补齐版本化兼容层，对 16 个固定脚本逐项验证并记录剩余限制；原方法保留。
5. 逐个跑功能与体验门、完整 `flutter analyze --no-pub` 和 `flutter test --no-pub -j 1`，统计所有通过、失败和跳过。
6. 有实际 Android 设备时验真实播放；无设备则明确未验证，不重装已清理的模拟器。不能把脚本初始化通过替代歌曲播放。
7. 用 D 盘原工具链、原依赖锁、稳定签名构建三 ABI 覆盖安装包；更新版本及中文交付文档。清理本轮临时产物，正式回归场景作为源码交付保留。
