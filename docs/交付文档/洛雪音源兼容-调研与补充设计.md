# 洛雪音源兼容：调研与补充设计

日期：2026-11-01。票据：视频同款-004。状态：用户回复“可以直接导入音源链接吧”确认 B；已实施并交付 0.3.0，真实链接导入与设置管理实测通过。0.2.0 的 HTTP 方案继续保留。第三方真实歌曲播放仍未验证。

## 背景与目标

用户提供 `pdone/lx-music-source`，希望使用其中的音源。该需求最终需要完成“选择仓库中的脚本 → 导入或连接 → 解析歌曲 → 实际播放”的链路。仅增加一个 HTTPS 输入框不能算完成洛雪脚本兼容。

初始调研读取 GitHub 仓库元数据、README、完整文件树，并静态查看 Huibq、LX、SixYin 三个脚本，以及连通性探测代码和工作流；该阶段没有执行第三方脚本。实施后已在正式 APK 的隔离沙箱中实际初始化 Huibq，未调用其真实歌曲解析接口。结论固定于提交 `000578ddca4a676012cf735abdc3489efdc67c74`，不保证未来仓库内容不变。

## 已核实事实

- 主分支包含 16 个 `latest.js` 音源入口；README 的在线导入链接均指向 JavaScript 文件。
- Huibq 脚本依赖 `globalThis.lx`，注册 `musicUrl` 动作，通过洛雪的请求与事件接口工作。它返回音频 URL，不是本应用要求的、含实际音质的 JSON 响应。
- 本次查看的 LX 与 SixYin 文件含混淆代码；仅静态检查不能证明其完整行为或适用于全部运行环境。没有对其余 13 个脚本做逐行行为审计。
- 完整文件树没有发现仓库级 LICENSE；GitHub 元数据的 license 为空。不能仅因仓库可公开阅读就认定所有脚本均允许重新分发；本次不将第三方脚本打进 APK 或源码交付包。
- `probe.py` 对提取的主机进行连接检查；README 的状态图片是服务连通性的线索，不是逐曲目、逐音质的实际播放验收。
- 当前仓库未提供本应用可直接部署的 `/v1/resolve` 网关。将 README 中的 `.js` 下载地址粘贴到 0.2.0 音源地址栏不会完成脚本导入。

## 两种实现方案

| 方案 | 用户操作 | 优点 | 成本与限制 |
| --- | --- | --- | --- |
| A：独立 HTTP 适配服务 | 在电脑或服务器配置音源，手机填写服务 HTTPS 地址 | 沿用 0.2.0 协议；不改安卓运行时；可单独升级和停用 | 需要持续可达的服务；外出使用需自己的 HTTPS 部署；每种上游仍需适配和验证 |
| B：手机内新增洛雪脚本运行时 | 在手机选择 `.js` 文件或填写脚本下载链接，检查信息后启用 | 更接近洛雪的直接导入体验，不要求电脑常开 | 新增脚本执行与网络桥、生命周期和资源限制；不同脚本的兼容范围必须逐个验证 |

若继续已确认的 HTTP 首版路线，推荐 A：先做一个独立适配器，明确限定一个经过核对的协议，不泛化为执行任意脚本。若目标明确为“手机直接导入仓库里的 `.js`”，则必须选择 B；A 不能被描述为已经满足这一体验。

先前 Jev 对首版约束的实际判断支持受限 HTTP 方案，结果记录于《自定义音源-设计与验收》。本次仓库事实来自直接读取代码，未让 Jev 代替代码检查，也未把先前判断当作全部脚本已验证的证据。

## 推荐 A 的接口与数据结构

安卓继续使用 `CustomSourceConfig`、`CustomSourceResolver` 和 `/v1/resolve`，不改公开签名或默认行为。独立服务提供：

```text
GatewayConfig
  upstreamBaseUrl: HTTPS URI
  upstreamCredential: 服务私有环境变量，可选
  clientToken: 服务私有环境变量，可选
  allowedPlatforms: qq / netease
  timeoutSeconds: 10

ProviderAdapter.resolve(request) -> CustomSourceResult
```

服务端将 `qq` / `netease` 映射到上游协议；仅根据该音源确有支持的档位映射音质。不把仅返回 URL 的上游响应直接标为“已经验证无损”；缺乏规格依据时返回明确的不支持结果。上游凭据由使用者提供，客户端仅持有自己的网关令牌，不包含 QQ 或网易云账号 Cookie。

连接测试使用保留 ID `connection-test`。网关仅验证协议与自身配置，不能用该探针代替真实歌曲播放。响应、错误码、HTTPS 要求和下载用途详见《自定义音源-HTTP接入协议》。

## B 所需的独立边界

如果选择 B，另增 `LxScriptSource` 和 `LxScriptResolver`，通过已有 `CustomSourceResolver` 接入。脚本正文保存在应用私有目录，导入元数据至少包括名称、版本、SHA-256、来源链接、启用平台及协议能力。缺省仍关闭，更新须显式操作。

脚本环境不能读取平台登录存储、文件系统或调用系统命令；网络仅经受控请求桥，取消、超时、响应体大小和资源耗尽均需可终止。先定义并验收最小洛雪事件/请求 API，不宣称兼容整个脚本集合。若脚本依赖尚未实现的接口，应在启用前显示具体的不支持项。

## 场景与先行验收门

以下为设计时列出的验收场景；实际实现、红绿证据与未覆盖项见文末，不能仅凭清单将全部记绿：

1. 用户配置一个源，连接成功、令牌错误、超时、协议不兼容分别显示明确状态，失败不自动启用。
2. QQ 与网易云歌曲 ID 和音质正确映射；不支持的档位被明确拒绝，不静默降音质。
3. 官方已成功时不调用适配服务；允许回退时真实解析一次并播放，界面显示来源与有依据的规格。
4. 切歌、禁用、删除和取消下载能终止对应请求；迟到响应不覆盖当前曲目。
5. 网关或脚本环境看不到平台 Cookie、本地路径和账号存储；上游令牌不出现在客户端日志和错误文案中。
6. 本地可控音频从解析到播放器进度推进的完整链路通过；真实第三方曲目验证单列，不用连通性或 URL 非空代替。
7. 若选择 B，再覆盖文件/链接导入、脚本语法错误、缺 API、初始化失败、恶意循环、过大响应和网络桥取消；逐个记录实际兼容脚本及 SHA-256。
8. 全量现有自动化门保持通过；发布包同签名覆盖安装，原配置与默认播放行为不变。

## 实施步骤与回滚

1. 用户确认 A 或 B，并明确是服务连接还是手机直接导入体验。
2. 写正式功能门与体验门，记录红门；A 的首个上游先确定协议、配置和规格证据，B 先冻结最小运行时接口。
3. 实现独立模块，保持现有接口及默认路径；逐个使门变绿。
4. 在专用模拟器完成实际播放链路，运行全量回归并出下一版本 APK。
5. 记录兼容范围，清理临时脚本、证书、音频和日志。回滚为停用新源/服务并恢复上一 APK；不改平台账号或收藏数据。

## 已确认 B 的实施细化

用户在上述方案提问后明确选择链接直接导入，因此采用 B。当前参考 Android 官方 JavaScriptEngine 文档与 AndroidX 源码，使用 `androidx.javascriptengine:javascriptengine:1.1.1`（官方发布页列为 2026-09-23 发布），由 `JavaScriptSandbox` 独立进程运行脚本。与 WebView 相比它无需网页、DOM 或平台网络权限；缺少独立终止/堆限制能力的设备直接显示不支持，不回退到主进程执行。

实际调用 Jev `jev-1.14.0` 的 runtime 选择为 isolated_engine，概率 0.78，confidence 0.56；结果有一定倾向但置信度有限，只作辅助。用户指定的本机 `jev.ps1` 路径不存在，因此依据 Jev 技能直接使用环境中的密钥调用官方接口；首次省略 model 被接口拒绝，补充 `jev-latest` 后成功。未记录或输出密钥。

### 接口、数据与接线

- 新增独立 `LxSourceConfig`：原始链接、脚本正文、SHA-256、声明名称/版本、支持平台/档位、enabled=false、allowForDownloads=false。以新的 Hive 键保存，不覆盖 HTTP 配置键。
- 新增 `LxSandbox` 接口：create、evaluate、close；Android MethodChannel 只负责隔离执行，不接触账号和文件。每项操作具有独立 ID，可取消；脚本 1 MiB、堆 32 MiB、返回 256 KiB 上限，整体 15 秒默认超时。
- 新增 `LxSourceRuntime`：实现最小 `lx.on / send / request / EVENT_NAMES / env / version / currentScriptInfo`，包含定时器；网络通过独立 Dio，不复用平台的 Cookie/interceptor，限制请求数、正文大小、HTTPS 与重定向。未实现的 utils 能力抛可读错误，不能假装成功。
- 新增 `LxCustomSourceResolver` 实现既有 `CustomSourceResolver`，`tx/wy` 映射 QQ/网易云，`128k/320k/flac/flac24bit` 对应可支持的档位。仅 URL 返回时显示“规格未验证”，不凭请求档位编造实测码率。HTTP 与洛雪源互斥启用，不自动轮询多个源。
- 设置入口保留，新增“音源链接导入”，下载/初始化成功才显示待保存卡片；显式保存和开启才用于播放。支持重新导入更新、测试初始化、禁用和删除。导入失败保留旧配置。
- 导入链接只允许 HTTPS；GitHub 的具体 blob 文件链接转换到 raw 域名；仓库首页、HTML 内容、空文件、非脚本和过大响应报错，绝不执行网页内容。

### 受影响调用方与回滚

修改仅为新入口设置接线、播放/下载的可选解析器选择、安卓插件注册的独立包条件，以及独立构建版本升至 0.3.0。`MainActivity.configureFlutterEngine` 只在 `packageName == app.videomusic.player` 注册新增插件；方法签名、原插件注册与其他逻辑不变。AndroidX 依赖用于新增插件，不替换旧依赖。原平台、旧入口及既有公开方法不改。

回滚为停用洛雪配置，移除上述 opt-in 接线和插件，恢复 0.2.0 独立构建号；HTTP 配置、官方账号和收藏数据不迁移。对已安装新版回滚源码重新出包时仍须递增构建号，不能要求用户清数据。

### 本轮正式红门

实现前新增正式导入/协议测试和 UI 测试，另保留设备脚本隔离验收入口（仅显式构建该验收入口时运行）。覆盖无效链接、GitHub blob 转 raw、真实下载限额、HTML/无元数据脚本、初始化失败、元数据平台与档位、取消/超时关闭沙箱、网络桥不夹带平台会话、QQ/网易云映射、无配置默认不调用、显式启用与删除、导入错误保留旧配置。设备门执行真实沙箱的正常初始化、异步请求、死循环终止及再次创建运行；正式交付 APK 不包含调试入口。

## 0.3.0 实际验收结果

正式新增功能 11 门、体验 6 门。模块不存在时执行得到编译红门；随后流式超限测试先失败（仍接收完 4096 块），增加实时接收进度取消后通过；空音质平台声明先被错误接受，收紧到至少一个非空支持档位后同门通过。相关 HTTP/LX/i18n 定向合计 51 通过。全工程静态 0 issue；完整测试 1760 通过、11 个上游既有跳过、0 失败，5 分 34 秒。未抽样、未新增 skip。

Android 36 / WebView 133 专用模拟器实际执行 6 个沙箱门：定时初始化、异步请求与歌曲 ID、死循环超时、超时后重新运行、取消独立任务、无 require/fetch/Java/process/document 入口。网络桥的歌曲响应为可控数据，不能当作真实歌曲播放证据。

正式 `lib/main_video.dart` 三架构 release 构建成功后，x86_64 同签名覆盖安装并冷启动，实测 Huibq 链接导入、默认关闭、显式启用保存、强制退出重启后仍保留、测试初始化、关闭保存、取消删除、确认删除恢复“未配置”及原 HTTP 页面入口。截图 13–16 为该最终 APK 的真实界面。
