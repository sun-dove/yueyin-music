# 自定义音源：设计与验收

日期：2026-10-31。票据编号：视频同款-003。

状态：**HTTP JSON 首版已按用户确认实施于 0.2.0，并在 0.3.0 保留；真实 HTTP 服务播放门仍未执行。** 更新日期：2026-11-01。以下首版选型描述仅适用于 HTTP 模块；用户随后确认的直接链接导入已作为 0.3.0 独立洛雪运行时实施，范围见《洛雪音源兼容-调研与补充设计》。

## 一、问题背景与目标

用户希望在“同款音乐”安卓应用中自行配置音源，用于在 QQ 音乐或网易云的官方取流不可用时，向用户指定的音源服务请求可播放地址。

目标是增加一个默认关闭、可随时移除的自定义音源能力，同时保持原入口、原 QQ / 网易云平台公开接口、已有账号、搜索、收藏、下载及默认播放行为不变。应用不承诺任何第三方音源能播放会员歌曲，也不把返回链接解释为已获得平台会员权限；用户及音源服务需对内容来源和使用授权负责。

洛雪桌面版的官方说明明确：程序把歌曲信息交给“自定义源”，源返回在线链接后进行播放，程序本身无法验证音频与目标歌曲是否匹配。其当前实现导入的是 JavaScript 脚本，脚本声明 `musicUrl` / `lyric` / `pic` 等动作，并在独立 Electron 窗口环境执行。直接照搬该脚本运行时会在安卓应用内引入不受信任代码执行、网络权限、长期维护及测试边界问题。

## 二、方案比较

### 方案甲：完整兼容洛雪 JavaScript 音源脚本

- 优点：可直接使用现有洛雪脚本；用户迁移成本低。
- 缺点：需要在 Flutter / Android 内新增 JavaScript 运行时及洛雪事件、请求、取消、更新协议；第三方脚本可主动联网，安全边界复杂；洛雪桌面运行环境与 Android 不等价；脚本协议变化会形成长期兼容负担。
- 结论：首版不采用。

### 方案乙：受限 HTTP JSON 音源

- 用户配置 HTTPS 服务地址、显示名称、启用平台、可选认证令牌和超时。
- 应用只发送当前歌曲的平台、歌曲 ID、名称、歌手、专辑及请求音质；服务只返回音频 URL、实际音质、格式、码率和可选有效期。
- 应用不执行源提供的脚本，不发送 QQ / 网易云 Cookie、二维码登录材料或账号令牌。
- 优点：接口小、错误可分类、易于测试；Android 直接支持；以后可由用户在自己的服务器上适配合法数据源。
- 缺点：现有洛雪脚本不能直接导入，需要音源方提供 HTTP 包装服务。
- 结论：**推荐首版采用。**

### 方案丙：WebView 沙箱执行洛雪脚本

- 优点：比完整原生脚本运行时更容易嵌入 JavaScript。
- 缺点：仍需暴露网络与消息桥，沙箱及取消语义复杂；后台播放、生命周期和调试成本高；安全风险只被转移，没有消失。
- 结论：首版不采用。

TypeSafe Jev `jev-1.14.0` 对上述具体约束的实际结构化判断选择方案乙，confidence 为 1.0；“首版应允许任意 JavaScript 音源脚本”的 `noul` 为 0.07。Jev 仅辅助比较方案，实际安全及兼容结论以上述源码和验收门为准。

## 三、推荐接口与数据结构

新增结构只用于视频同款入口，不修改 `PlatformType`、`MusicPlatform` 或旧平台方法签名。

### 本地配置

```text
CustomSourceConfig
  id: String
  name: String
  endpoint: HTTPS URI
  enabled: bool = false
  platforms: Set<qq | netease>
  timeoutSeconds: int = 10
  allowForDownloads: bool = false
  credentialRef: String?  // 令牌保存在安全存储，普通设置只保存引用
```

新增字段均可选，配置不存在或关闭时行为与改动前一致。第一版支持一个当前音源，数据结构保留稳定 ID，后续可以扩展多个音源及优先级。

### 请求

`POST <endpoint>/v1/resolve`

```json
{
  "requestId": "随机请求 ID",
  "platform": "qq",
  "song": {
    "id": "平台歌曲 ID",
    "title": "歌曲名",
    "artists": ["歌手"],
    "album": "专辑"
  },
  "quality": "high",
  "purpose": "play"
}
```

请求不包含平台 Cookie、登录令牌、手机号、二维码或本地文件路径。认证令牌只放在发往用户配置服务的 `Authorization` 头中，不写入日志、错误提示或普通 Hive 设置。

### 成功响应

```json
{
  "url": "https://media.example/audio.mp3",
  "quality": "high",
  "format": "mp3",
  "bitrate": 320000,
  "expiresAt": "2026-10-31T18:00:00Z"
}
```

`url` 必须是 HTTPS；0.2.0 同样要求本机服务使用 HTTPS。响应缺字段、URL 非法、过期或实际音质低于固定请求时均返回明确错误，不把失败伪装成成功，也不静默降音质。

### 错误响应

```json
{
  "error": {
    "code": "not_found",
    "message": "当前音源没有这首歌",
    "retryable": false
  }
}
```

固定类别至少包括：`not_found`、`quality_unavailable`、`unauthorized`、`rate_limited`、`timeout`、`source_unavailable`、`invalid_response`。类别驱动界面文案及“重试”按钮是否可用。

## 四、播放与下载策略

1. 默认继续使用当前 QQ / 网易云平台取流。
2. 只有当前歌曲原平台明确返回不可用、会员不可用或质量不可用，并且用户启用了匹配平台的自定义音源时，才请求自定义源。
3. 原平台发生认证过期、请求被取消、离线模式或应用内部错误时不调用自定义源。
4. 原平台已返回可用链接时不请求自定义源；不替换官方可播放结果。
5. 音源失败后显示“官方音源失败原因 + 自定义音源失败原因”，保留重试和设置入口，不继续换平台或降音质。
6. 下载默认不使用自定义源。用户在音源设置中另行开启“允许用于下载”后才可使用，并沿用现有下载完整性及离线播放检查。
7. 每次成功解析记录“自定义音源 / 服务名称 / 实际格式和音质”，不记录完整 URL 或令牌。

## 五、安全和隐私边界

- 首版不导入或执行 `.js` 音源文件，也不提供 `eval`、WebView 脚本桥或任意代码运行能力。
- 默认只接受 HTTPS；禁止 URL 中携带用户名和密码；本版不自动跟随重定向。
- 令牌使用 `flutter_secure_storage`，删除音源时同时删除；导出配置不包含令牌。
- 不把 QQ / 网易云会话、Cookie、账号 ID、二维码内容及本地文件传给音源。
- 设置页明确提示：第三方服务可看到请求的歌曲信息和设备网络地址；应用无法保证返回内容与歌曲匹配，也无法赋予会员权益。
- 用户必须主动保存并启用音源；导入链接或剪贴板内容不会自动启用。

## 六、验收门

所有正式门先写成红门再实现。功能门和体验门缺一不可。

### 功能门

1. 无配置及配置关闭时不创建音源请求，QQ / 网易云既有行为逐字保持。
2. 配置校验覆盖空名称、非 HTTPS、URL 带凭据、非法超时、无平台选择和重复 ID；合法配置往返持久化不丢字段。
3. 认证令牌只进入安全存储；Hive、日志、错误对象和配置导出中均不存在明文令牌。
4. 原平台成功时不请求自定义源；明确的歌曲不可用、会员不可用、质量不可用按策略触发；认证过期、取消、离线及未知错误不触发。
5. 请求字段与协议完全一致，不包含平台会话或本地路径；QQ 与网易云 ID、标题、歌手、专辑和音质映射正确。
6. 成功响应校验 HTTPS URL、有效期、实际音质、格式和码率；低于固定音质时失败，不静默降级。
7. HTTP 401 / 403、404、429、5xx、超时、取消、非 JSON、超大响应及未知错误均映射到固定错误类别，重试属性正确。
8. 歌曲 A 的迟到响应不能覆盖已经选择的歌曲 B；重复点击播放会取消旧请求并发起新请求。
9. 下载默认不调用自定义源；用户显式开启后才调用，并保留现有下载路径、进度、校验、取消、重试及离线播放契约。
10. 删除或禁用音源后立即停止新请求、取消在途请求、清除令牌；已有官方播放及本地文件不受影响。

### 体验门

1. “我的 → 播放设置”显示“自定义音源：未配置 / 已关闭 / 已启用（名称）”，可进入管理页。
2. 新建页包含名称、HTTPS 地址、适用平台、超时、令牌及下载开关，并显示隐私和授权说明；令牌默认隐藏。
3. 保存前“测试连接”分别显示成功、认证失败、协议不兼容、超时和服务不可用；失败时配置不自动启用。
4. 官方音源成功时播放器不显示自定义源提示；实际使用后播放器显示“来源：自定义音源 · 名称”和真实音质。
5. 双源均失败时同时展示可读原因，并提供“重试”和“音源设置”；不可重试错误不显示误导性的重试按钮。
6. 删除音源前展示名称及影响范围；确认后页面立即显示未配置，返回播放页不再调用。
7. 主题、返回键、键盘、窄屏、长名称和无障碍文本缩放下均可完成配置，不遮挡保存及测试按钮。

### 任务评测门

- 使用本地可控 HTTPS fixture 在安卓模拟器完成保存、连接测试、官方失败后自定义解析、播放进度推进、错误与重试、禁用及删除全流程。
- 使用用户自己的合法音源服务和一首有授权的歌曲完成真机播放；比对请求歌曲和实际声音，验证应用无法仅靠 URL 自动确认内容正确。
- 未提供服务或授权歌曲时，该真实门记为未执行，不用公开第三方音源或会员歌曲替代。

## 七、实现步骤与回滚

1. 在 `video_app` 内新增配置、协议客户端、错误类型和安全存储适配器，不改旧平台接口；先提交上述功能门红测结果。
2. 给新入口使用的播放包装层增加可选解析器；默认 `null`，确保旧构造与行为不变。仅实现已列明的失败触发矩阵。
3. 增加音源设置和连接测试界面，再补体验红门并实现。
4. 定向门变绿后执行全工程静态检查和全部测试；重建三架构分包 APK，并在专用模拟器跑任务评测门。
5. 清理 fixture、日志、临时证书和测试音频；正式协议文档与验收用例长期保留。

回滚时删除新配置页、客户端和可选解析器接线；由于旧 `MusicPlatform`、`PlatformType` 和默认入口不改，且新增配置默认关闭，旧播放路径可直接恢复。删除配置时清除安全存储中的音源令牌。

## 八、需要确认的实现范围

推荐首版实现方案乙：可配置一个受限 HTTP JSON 音源，支持 QQ / 网易云播放，下载需单独开启；不直接导入洛雪 JavaScript 脚本。确认后按上述门先行实施。
