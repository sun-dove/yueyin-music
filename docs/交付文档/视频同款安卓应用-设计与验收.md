# 视频同款安卓音乐应用：设计与验收

日期：2026-10-29。票据编号：视频同款-001。

状态：**设计已由用户确认，已产出可安装的安卓 APK。** 用户已确认目标为可安装的安卓 APK，并回复“开干”；后续“继续”延续该授权。目标是接入真实 QQ 音乐、网易云账号与播放能力，界面及操作尽量贴近所提供的视频。已交付产物、逐门通过范围与尚未执行的真实账号和真机验证，见同目录《同款音乐-逐门验收报告.md》；以下设计目标不等于全部能力已经验收通过。

本文件与《视频界面对照.png》为正式设计交付物。截图是原始视频参照，不是已经完成的应用。

## 一、问题背景与目标

目标是在一个安卓应用中，以视频中的四个入口完成双平台搜索、查看与同步“我喜欢”、真实音乐播放、歌词显示、音质设置、缓存与下载。交付标准同时包含视觉、交互和真实数据能力。

原始视频长约 25.77 秒，画面为 576 × 1280。用户没有提供原应用名称或源码，不能据此声称取得了同款原项目。录屏者的昵称、歌曲、封面、383/124 首收藏和 1009/298 条搜索结果均为示例数据，实际应用须读取当前账号及查询结果。

设计时工作区没有用户生产项目，命令路径中未发现 Flutter、Dart、ADB，常规路径未发现安卓 SDK。实施已在任务局部目录安装所需工具链，不改变全局配置；该段是设计时环境记录，构建与真机验证结果另见实施记录。

## 二、视频中的真实场景

精确时间点以直接取帧为准，见同目录《视频界面对照.png》。

| 场景 | 参照时间 | 应还原的可见行为 |
|---|---|---|
| 我的 | 0 秒及 1 秒 | 双平台账号卡片、退出、同步状态；收藏及本地歌曲数量；播放音质、播放缓存、下载音质、存储占用、主题 |
| 网易云 | 2 秒 | 网易云标题、红心歌单卡片、我喜欢的歌曲列表；与 QQ 页相同的结构 |
| QQ 音乐 | 3 秒、22 秒 | 我喜欢的音乐、歌曲数、总时长、播放全部、下载、歌曲行、红心和正在播放行 |
| 搜索首页 | 4 秒 | 搜索框、来自 QQ 音乐的热搜榜、点击或输入查询 |
| 搜索结果 | 8 秒、11 秒 | 本地 / QQ 音乐 / 网易云切换；平台结果数、已加载数；歌曲列表、音质标记、收藏与更多菜单 |
| 全屏播放器 | 9 秒、13 秒、18 秒 | 从迷你播放器进入；大圆角方形封面、封面配色背景、当前歌词、歌曲信息、音源及音质、进度、上一首、播放暂停、下一首、随机播放和队列入口 |
| 全屏歌词 | 20 秒 | 封面区域收起、歌词展开，当前行强调；保留进度和播放控制 |
| 切页与收起播放器 | 11 秒、14 秒、22 秒 | 播放持续；迷你播放器和全屏播放器共享当前曲目与进度 |

登录过程、音质选择弹层、完整下载管理和队列详情未在视频中完整展开，按同一视觉风格补齐。深色主题按“跟随系统”的设置补齐。手机状态栏、输入法和系统导航条由系统提供，不作为应用自身组件复刻。

## 三、至少两个实现方案的比较

| 方案 | 做法 | 优点 | 代价与待验证项 |
|---|---|---|---|
| 甲：新增同款界面，复用开源基础 | 固定 Mconnect 源码版本，新增独立入口、界面和数据适配层；复用可用的平台底层、音频服务和存储 | 已有 Flutter、后台音频、账号存储和平台接口基础；工作集中在视频场景及真实缺口 | 不能直接复用所有高层方法；需验证登录、全量收藏、错误处理和音质 |
| 乙：原生从零实现 | Kotlin + Jetpack Compose + Media3，重新实现双平台接口、登录、歌词、下载和后台服务 | 架构完全围绕本次界面目标组织 | 需要重新完成和验收平台协议、账号会话、音频及下载生命周期，工作面明显更大 |

**推荐方案甲，包含独立界面和数据能力补齐。** 本次源码审查基线为 [`9df0c0feeb148d65cebe51fea5fe8d4387e16dcc`](https://github.com/Hjdd14/Mconnect-Music_connect/commit/9df0c0feeb148d65cebe51fea5fe8d4387e16dcc)，对应近期发布 v1.5.0。已读取的许可证为 MIT；依赖声明和启动入口包含所需基础。正式接入固定该提交并保留许可、版权及第三方声明，不追随 main 自动升级。

源码审查发现的具体缺口必须先有验收门：

1. QQ 收藏高层方法默认获取一页，不能把默认 50 首冒充完整同步。
2. 部分异常被捕获后返回空列表，不能直接驱动“没有收藏”界面。
3. 现有 QQ 文件格式映射主要为 MP3/FLAC，没有已核实的 OGG 640 支持；静态音质列表也不能证明某首歌可播该音质。
4. 网易云收藏方法按歌单名称匹配并可能回退到首个歌单，不能据此认定那就是“我喜欢”。

这些缺口由新增数据适配层处理；如底层缺少必要能力，优先新增明确命名的方法。真实接口不通过时保留失败记录，不能通过假数据或错误标记让验收变绿。

## 四、界面与交互设计

### 统一外观

- 底栏固定为“搜索 / QQ 音乐 / 网易云 / 我的”，顺序和图标含义贴近视频。
- 浅灰偏紫背景、白色圆角卡片、蓝紫强调色，歌曲封面保留圆角；播放器背景取当前封面的浅色调。
- 以 576 × 1280 画面比例做首个截图对照，布局适配常见安卓屏宽、系统安全区域和字体缩放，不把视频物理像素直接当作布局单位。
- 迷你播放器位于底栏上方；点击展开全屏，收起后返回原入口、列表及滚动位置。切页不重建播放会话。
- 列表当前曲目以淡紫色背景及播放状态标记显示；收藏状态来自当前平台，不能跨平台共用一个未经确认的红心状态。

### 搜索

空输入时显示热搜；提交后分别查询平台，默认展示 QQ 结果，保留本地及网易云入口。每个平台独立维护加载、结果、错误和分页状态。平台总数未知时不伪造总数；旧查询迟到响应不能覆盖新查询。滚动至底部继续加载，保留列表位置。

### 平台收藏页与我的

两个平台分别登录、同步和退出。平台页展示真实“我喜欢”及总时长；同步完整后才显示“已同步”。同步部分完成时显示已获取数量和继续/重试入口。账号过期时保留可识别的本地收藏快照并标明需重新登录，不假称最新。

“我的”播放音质与下载音质独立保存。缓存上限按视频提供 10240 MB 的初始设置，不预分配空间；实际占用来自真实文件。可清理缓存、选择上限和查看下载。主题默认跟随系统。

### 播放、歌词和音质

点击可播歌曲后展示“准备中”，取得地址并开始实际音频播放后进入播放态；全屏与迷你播放器共享歌名、封面、进度和错误状态。可切换封面与全屏歌词，歌词按时间轴高亮，支持点击某行定位播放。

支持顺序、单曲与随机播放，队列与底栏入口一致。后台和锁屏播放需要真机验收。切歌时清除上一首歌词和音质信息，不能残留。

请求音质与实际音质分别保存。OGG 640 须有真实接口响应及实际媒体验证，才作为可用选项和实际标记展示。请求档位不可用时明确提示，并提供选择可用档位的操作；默认不静默降档或跨平台换源。明确识别试听，不能把试听标成完整歌曲。

### 未展开的页面

登录采用经核实可用的平台扫码/授权流程，账号权限在用户设备上完成。下载管理展示等待、下载中、完成和失败，支持取消、失败重试及离线播放。队列详情支持选播与移除；下载和队列入口可以操作，不能只做静态按钮。

## 五、接口、数据结构与兼容边界

### 新增层的职责

建议新增独立入口 `lib/main_video.dart`，界面放在独立的 `video_app` 目录，另设平台数据适配器。具体路径在固定源码后落定。现有入口、路由和公开方法保持原签名、原返回类型及原行为；新增界面通过明确的适配器调用已核实能力。

可复用的公开接口包括 `AuthNotifier` 的初始化、二维码登录与退出，以及 `PlayerNotifier` 的 `playSong()`、`playPlaylist()`、`togglePlay()`、`switchQuality()`、`seek()`。全屏与迷你播放器监听同一个 `playerProvider`。新外壳自行接好会话初始化、后台音频和生命周期；原应用外壳路由是固定的，不强行修改它。收藏分页使用已有低层 `QqApi.getLikedSongs(page, limit)` 能力新增完整结果封装；搜索的旧返回类型只有歌曲列表，总数通过新适配层承载。

| 新增结构 | 最少字段及含义 |
|---|---|
| 曲目标识 | 平台、平台歌曲 ID；两者联合唯一 |
| 曲目视图 | 标识、标题、歌手、封面地址、时长；可选的收藏状态、可用音质、试听状态；未知不能解释为否 |
| 分页结果 | 本页曲目、可选的平台总数、下一页标记、是否有后续；已加载数取当前去重集合大小 |
| 收藏同步状态 | 平台、未开始/进行中/部分完成/完整/失败、已获取数、可选总数、错误；只有穷尽分页才能记完整 |
| 账号状态 | 平台、未登录/有效/过期、可选昵称与头像；与收藏同步状态分开 |
| 播放状态 | 曲目、准备/播放/暂停/失败、进度、实际时长；可选请求音质、实际音质、试听状态和错误 |
| 操作结果 | 成功数据或明确失败；错误类别、可显示说明、是否可重试、建议操作 |

这些是新增结构，不要求给既有模型增加必填字段。确需扩展旧结构时只加可选字段，缺省保持原行为。

### 体验反向定义的错误分类

| 错误类别 | 用户看到什么 | 可用操作 |
|---|---|---|
| 未登录 / 会话失效 | 对应平台需要登录，区分尚未登录与已过期 | 登录；另一平台仍可使用 |
| 曲目权限不足 | 当前账号暂无该曲目或音质权限 | 选择已核实可用音质、返回；不能无限重试 |
| 资源不可用 / 地址失效 | 曲目暂不可播放 | 地址失效时重新取流；否则返回 |
| 网络失败 | 加载失败且保留已有结果 | 重试 |
| 存储授权不足 / 空间不足 | 下载无法保存，说明具体原因 | 授权 / 选择目录 / 释放空间后重试 |
| 未知错误 | 当前操作失败 | 安全重试或返回，并记录诊断信息 |

平台错误码与上述类别的映射采用确定性规则并纳入测试。产品运行不引入 Jev 或其他大模型依赖来决定错误分类、分页、播放状态或账号权限。

如最终确实必须改动已有代码路径，须先在票据补充：原因、完整调用方清单、回滚办法和负责人确认；本次设计确认不等于对未知修改的笼统授权。构建接入若需新增配置，也应保持旧默认配置不变并明确差异。

## 六、场景与验收门

**以下是设计时建立的门清单，初始状态均为“未实现 / 未执行”。** 实施时先把确定性门写为可执行用例，运行并记录失败，再实现对应场景；当前结果见《同款音乐-逐门验收报告.md》，不能把本表中的设计要求直接记为已通过。用户已确认覆盖这些门的必要自动化验收用例作为正式交付源码长期保留，支撑后续回归与连续集成；临时调试测试、样例、缓存、帧图和脚本在结束前删除，用户原有测试一律保留。

| 门 | 真实场景与体验门 | 确定性功能门及执行方法 | 额外实机/产物门 |
|---|---|---|---|
| 门01 | 打开四入口，视觉与视频一致，播放器持续 | 组件用例依次点击全部入口，核对入口顺序、当前曲目和播放状态；固定样例截图对照全部主界面 | 真机按参照图逐屏录屏、截图；同时确认全屏歌词 |
| 门02 | QQ/网易云独立登录、过期、退出 | 对每个平台完整执行未登录/成功/过期/退出；断言会话及界面状态不串号 | 两个真实账号分别扫码；退出一个不影响另一个 |
| 门03 | 我喜欢全量同步，成功/空/部分/失败可区分 | 固定 76 首、每页 30 首，跑到第 3 页；核对完整去重 ID 集合；额外覆盖重复页项、中途失败、真空列表和失效会话；网易云不得回退错歌单 | 两平台分别比对真实完整列表与平台报告数量；无法核对全量时明确报告范围，不记全量通过 |
| 门04 | 搜索五月天或任意词，跨平台切换并加载更多 | 固定多页结果全量拉取，核对总数/已加载数/顺序/唯一性；模拟旧请求晚返回和一个平台失败 | 真实搜索、切页、滚动至末页，保留完整场景记录 |
| 门05 | 空结果、网络失败、会话过期与权限不足有不同提示和按钮 | 对每一错误类别逐个注入固定响应并核对界面和按钮状态，不允许返回空列表冒充错误处理 | 真机断网、恢复网络和重新登录 |
| 门06 | 点击真实歌曲，迷你与全屏播放同步 | 用明确时长的可用音频核对准备→播放→暂停→恢复；检查进度推进、队列及切歌清理 | 真机可听见音频；锁屏至少 60 秒，验证通知栏控制及恢复 |
| 门07 | 当前歌词与播放一致，能进入全屏歌词 | 固定时间轴逐点核对高亮；覆盖无歌词、切歌和点击歌词定位 | 真机观察滚动、封面/歌词切换、上一首/下一首 |
| 门08 | 音质真实，设置与实际值区分；试听明确 | 覆盖可用/不可用/实际返回不同/试听；独立核对播放及下载偏好；OGG 640 须通过实际响应与媒体检查 | 用有对应权限的真实曲目验证；不支持时该能力门保持未通过，不能假标 |
| 门09 | 下载完成可离线播放；失败可操作 | 校验真实文件、任务状态、取消、重试、空间和授权错误；错误类别驱动按钮 | 断网播放完成下载的文件，重启后仍可访问 |
| 门10 | 本地音乐和缓存数量真实，主题跟随系统 | 用已知文件集核对歌曲和缓存统计、清理及上限；浅/深色全主界面截图 | 真机选目录、清理缓存、切换系统主题 |
| 门11 | 新入口可运行且旧能力保持 | 固定上游版本，运行既有已绿检查及本次新增兼容检查；记录全部结果；不得静默跳过或只测前 N 个 | 产物安装、冷启动、完整复演视频操作链；原入口构建与行为核对 |

两层验收分开记录：

- 确定性门：固定数据、状态机、错误分类、分页不变量、媒体及文件结果；不包含大模型。按本设计确认的正式验收用例纳入连续集成必跑范围。
- 任务评测门：按最终 APK、真机录屏、完整操作场景与截图判定是否可用，报告逐场景通过数与失败原因。总体比例不能掩盖登录、全量同步或实际播放等核心场景失败。

没有真机或账号时，相关实机门标为“未执行”，不能以静态检查或模拟数据替代。任何平台或能力未覆盖都写入结果。

## 七、按场景落实的实现步骤

1. 设计确认后建立独立工程副本，固定上游提交，整理许可与构建环境；先记录原有可通过检查，并创建门01—门11对应的首批可执行红门。优先验证门02、门03、门08涉及的真实接口可行性。参考源码要求 Flutter 3.47.5 / Dart ^3.13.0、Java 17、AGP 8.11.1、Gradle 8.14；版本须以固定基线实际构建为准。
2. 完成“我能打开四个入口并切页”的场景：新增主题、底栏、列表框架及独立入口，使门01可检查；随后逐步接入真实状态。
3. 完成“我能分别登录并看到完整收藏”的场景：独立账号与收藏适配器，使门02、门03通过。
4. 完成“我能搜到并逐页查看全部结果”的场景：搜索、取消旧请求影响和逐平台错误，使门04、门05通过。
5. 完成“我能听歌、切页、看歌词和锁屏”的场景：统一播放器及队列，使门06、门07通过。
6. 完成“我能确认音质、下载并离线听歌”的场景：真实音质检测、下载及错误操作，使门08、门09通过。
7. 完成“我能管理本地歌曲、缓存和主题”的场景，使门10通过；全场景复演及旧能力回归使门11通过。
