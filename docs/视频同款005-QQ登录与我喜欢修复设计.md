# 视频同款005：QQ 登录与“我喜欢”修复设计

日期：2026-11-02。状态：用户已确认修复并出下一覆盖版本。

## 背景与目标

现象有两种：扫码后不能登录；或页面显示登录成功，但同步不到 QQ“我喜欢”。无账号网络探针确认二维码图片与 `qrsig` 仍能取得，因此故障位于扫码确认后的凭据交换及登录后收藏读取。

当前实现沿用旧 QQ 网页 OAuth 参数，并只要 Cookie 中出现普通 QQ `uin` 就可能建立用户状态。当前参考实现要求授权回跳包含 `login_type=1&surl=https://y.qq.com/`，作用域为 `get_user_info,get_app_friends`，并使用 `openapi=1010_1030`、随机 state、auth_time 与 ui；最终只有 `QQConnectLogin.LoginServer/QQLogin` 返回有效 `musicid`、`musickey`、`loginType=2` 才算 QQ 音乐登录完成。

当前“我喜欢”调用旧 `music.musicasset.SongFavRead/GetUserFavSongList`。新实现将账号内建“我喜欢”作为目录 `dirid=201`，通过 `music.srfDissInfo.DissInfo/CgiGetDiss` 读取，并要求登录凭据中的 `encryptUin` 作为 `enc_host_uin`。

目标是更新独立视频入口实际使用的 QQ 登录和收藏契约，避免假成功，恢复完整分页；原公开方法签名、原 Mconnect 入口和非 QQ 平台行为不变。

## 方案比较

### 方案 A：继续修补旧收藏 RPC

保留旧 OAuth 和 `SongFavRead`，只放宽返回解析。改动小，但无法解决凭据不完整；参考实现已迁移到固定目录读取，继续修旧接口缺乏依据。

### 方案 B：更新完整凭据交换，并将“我喜欢”切到固定目录

保留 `QqApi.completeOAuthLogin`、`getLikedSongs` 等公开签名，内部更新授权请求、验证最终凭据、把 `encryptUin` 以兼容 Cookie 字段保存，收藏读取改为 `CgiGetDiss(dirid=201)`。这是推荐方案，因为登录成功条件能直接支撑喜欢列表请求。

## 接口与数据结构

- `QqApi.completeOAuthLogin(String)`：签名不变；成功时 Cookie 必须包含 `qqmusic_uin`、`qm_keyst`、`qqmusic_key`，并在响应有 `encryptUin` 时保存内部兼容字段 `qqmusic_encrypt_uin`。
- `QqApi.getLikedSongs({page, limit})`：签名不变；将页号转换为 `song_begin`，调用 `music.srfDissInfo.DissInfo/CgiGetDiss`，参数含 `dirid=201`、`userinfo=true`、`orderlist=true`、`enc_host_uin`。
- 旧会话缺少 QQ 音乐 key 或 `encryptUin` 时不返回假空列表，按会话失效处理并要求重新扫码。
- 登录页收到扫码完成后，只有 `onQrLoginSuccess` 返回非空用户才提示成功和退出；否则显示失败并留在页面。

## 场景与验收门

1. 当前授权请求精确携带 redirect URI、scope、state、openapi、auth_time、ui；回跳 state 不匹配时失败。
2. `QQLogin` 缺 `musicid`、`musickey`、`loginType=2` 任一项不能建立登录状态或保存会话。
3. 登录页不能把空用户显示为成功。
4. “我喜欢”使用 `dirid=201`、正确分页和 `enc_host_uin`，解析 `total_song_num` 与 `songlist`。
5. 旧会话缺新凭据时显示会话失效，不把空列表当真实零首。
6. 原搜索、播放、二维码 66/67 状态、网易云和旧公开接口门保持通过。

## 调用方、回滚和限制

### 0.3.2 收口的兼容落实

为严格保持原入口行为，实际采用追加方法 `completeMusicOAuthLogin`、`getMusicLikedSongs`，由 `VideoQqApi` 在独立入口选择。既有 `QqApi.completeOAuthLogin`、`getLikedSongs` 与旧回跳常量保持原实现；`requiresCompleteMusicSession` 缺省为 false，独立适配器才启用完整凭据校验。上文内部直接替换的方案细化为此追加实现，目标与数据契约不变。

登录页的凭据确认期间显示加载状态；失败显示“登录凭据不完整，请重新扫码”，留在原页面且可以重试。场景门已实际发现“凭据尚未确认就显示登录成功”，先红后修正。

受影响调用方为 `QqPlatform.pollQrStatus`、`AuthNotifier.onQrLoginSuccess`、登录页成功分支、`VideoCatalog._syncQq`。回滚为恢复 0.3.1 的内部请求实现；数据结构未迁移，用户可重新扫码。真实账号扫码、完整喜欢数量和写入仍必须在用户手机验收；自动化仅验证协议契约，不伪造账号成功。
